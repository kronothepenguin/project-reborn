# Implementation Plan: Central Store Library

**Branch**: `013-store-library` | **Date**: 2026-09-12 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/013-store-library/spec.md`

## Summary

Create `packages/store`, the project's persistence infrastructure module. It opens one embedded SQLite file shared by every application, always enables foreign keys and WAL journaling, applies declared schemas idempotently at startup, exposes typed query/mutation operations generated by sqlc from `.schema.sql` / `.query.sql` files, supports atomic units of work, and classifies storage errors. The module owns no domain tables: features add their schema and query files incrementally, document them as OKF concepts in the module's `knowledge/` bundle, regenerate with sqlc, and consume the generated operations. Two reusable agent skills are delivered: one that defines the OKF format with a checklist and authoritative links, and one that walks a contributor from a data need to working typed operations.

## Technical Context

**Language/Version**: Go 1.27 (workspace `go.work`), module `github.com/kronothepenguin/project-reborn/packages/store`

**Primary Dependencies**: `modernc.org/sqlite` v1.58.x (pure Go, BSD-3-Clause); `github.com/sqlc-dev/sqlc` v1.31.x as a `tool` directive; standard library `database/sql`, `embed`, `errors`, `testing`

**Storage**: SQLite 3.53.x embedded single file per deployment; DSN `file:<path>?_pragma=foreign_keys(1)&_pragma=journal_mode(WAL)&_pragma=busy_timeout(5000)`; each pooled connection receives the pragmas; pool pinned to one connection per process to serialize writes and avoid `SQLITE_BUSY`

**Testing**: `go test ./...` from the module directory, `-race`; temp-file databases via `t.TempDir()`; pragma assertions after open; multi-connection and subprocess contention tests; in-memory shared-cache only for tests that do not need WAL

**Target Platform**: Server-side Linux/macOS/Windows (pure Go, CGO not required)

**Project Type**: Go library + two agent skills + OKF knowledge bundle

**Constraints**: `foreign_keys` and `journal_mode=WAL` always on; schemas additive and idempotent; no domain data in the module; generated Go committed and kept in sync (`go tool sqlc generate` + clean-diff gate); no CGO

**Scale/Scope**: One database file per deployment; schemas grow one feature at a time; the module starts with only a `Ping` smoke query and a reserved schema placeholder so the generation pipeline is exercised end to end

**Structure Decision**: The store is a new workspace module at `packages/store` (added with `go work use ./packages/store`), following the repository's packages-vs-apps rule. Schema, query, and knowledge files live in fixed subdirectories so the persistence skill has deterministic locations. The two skills live under the existing `.agents/skills/` tree, matching every other project skill.

## Addendum 2026-09-16: process store accessor

**Decision**: the store gains `func Must() *Store`, the single process
accessor for the deployment database.

- `Must` reads the path from `config.Must().Database.Path`; the `database`
  section is declared by this addendum under `packages/config/database`
  (`Path`, default `habbo.db`, non-empty validator).
- The first call opens with `store.Open` and caches the instance process-wide
  (`sync.Once`), so every package and app shares one store.
- A load or open failure panics with the underlying error,
  `template.Must`/`config.Must` style; there is no fallback and no retry.
- `Open(path)` stays for tests and tools that need isolated stores.
- `doc.go` and `knowledge/store.md` document the accessor and the
  one-store-per-process contract.

**Rationale**: the CMS and the future game server need the deployment store
without threading a path or `*Store` through constructors. The path is
deployment configuration, so it lives in the config layer, and the accessor
mirrors `config.Must`.

**Structure additions**:

**Gates**: `packages/config` runs `gofmt -l . && go vet ./... && go test ./...`;
`packages/store` runs `go vet ./... && go test ./...`, `make check-docs`, and a
clean `go tool sqlc generate` diff.
