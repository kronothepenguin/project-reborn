# Spec: 007 — Pack (virtual files + definition contract)

**Feature**: `007-pack` | **Branch**: `007-pack` | **Date**: 2026-09-09

## Problem statement

Director movies/casts are folders of translated JavaScript on disk
(`apps/client/src/game/<name>/`). To play them, the 008 player needs one module
per movie/cast whose **default export is a pure-data definition** the ingester can
consume. The `index.js` must be generated (not hand-written — 63 cast folders),
the builder DSL (`pack/cast.js`, `pack/movie.js`) must produce the **same shape**,
and a placeholder skill (`director-cast-to-javascript`) must be made real.

## Goal

1. Define the **MovieDefinition / CastDefinition / MemberDefinition / ScoreDefinition**
   contract (C8) shared by builders, generators, and the 008 ingester.
2. A Node generator (`generate-pack.mjs`) that turns decompiled
   `Casts.csv` + `Members.csv` into the `index.js` per cast and per movie.
3. Generate the **habbo** + **fuse_client** packs (C9) under `apps/client/src/game/`.
4. Builders aligned to the same contract (already landed inside 008's Phase D).
5. The `director-cast-to-javascript` skill documents + wraps the generator.

## Definition contract (C8 — the stable shape)

Frozen, pure data. No functions, no live objects.

### CastDefinition

```js
{ kind: "cast", name: "fuse_client", members: MemberDefinition[] }
```

### MemberDefinition

```js
{
  kind: "member",
  name: "Initialization",        // canonical identity
  mediaType: "script" | "bitmap" | "field" | "text" | "sound" | "button"
            | "colorPalette" | "cursor" | "font" | "empty",
  payload: { content }         // script/text: JS source string
         | { data, width, height }  // bitmap: base64 data URI
         | { audioBytes }       // sound: inline bytes
         | { text }             // field/text/button
         | { colors } | { glyph } | { glyphs }   // palettes/cursor/font
  registrationPoint: "(x, y)"  // from Members.csv, kept as metadata
  number?: 1-based registration order (metadata only; name is canonical)
}
```

### MovieDefinition

```js
{
  name: "habbo",
  totalCastSlots: 73,                    // max Number in Casts.csv
  casts: CastDefinition[],               // slot 1..N; empty slots = { kind:"cast", name, members:[] }
  options: { tempo: 30, width: 640, height: 480, src: "" },
  score?: ScoreDefinition                // optional, seq 004 contract
}
```

### ScoreDefinition

Optional `score` section per 004 `contracts/lifecycle.md` — data structure
modelled; playback runs with an empty score (Lingo-driven stage, `puppetTempo`).

## Decisions (agreed with user, 008 co-plan)

- **C8 shape above** is shared by builders, generator, ingester.
- **C9**: generate only **habbo** (73 slots: Internal 4 members + `fuse_client`
  cast import + 70 empty) and **fuse_client** (89 members) in this spec. The
  other 61 cast folders are mechanical re-runs of the generator later (not in
  this feature's scope).
- Generated files are **checked in** (built artifacts become virtual files the
  browser imports).
- `index.js` header: `// Generated by director generate-pack (007) — do not edit by hand.`
  + C8 conformance note.
- Casts are keyed by **name**; `number` is registration order only.

## Open items resolved

- Movie↔cast wiring: `Casts.csv` slot name → sibling `../<name>/index.js` import.
  Missing sibling dir → empty cast. The movie's **own internal cast members**
  live in `<movieDir>/Internal_Members.csv` (or `Members.csv`) — embedded
  inline (no separate dir). ✅ (fix landed during 008 Phase D)
- Bitmap payload: `pixels` renamed `data` (base64 data URI). ✅
- Logo/media row with no `Filename` / missing file → `payload: {}`. ✅

## Out of scope

- The other 61 cast folders (mechanical; deferred).
- Binary `.cst`/`.dcr` parsing (ProjectorRays CSVs are the input).
- Lingo→JS translation (the `.js` siblings are already translated).
