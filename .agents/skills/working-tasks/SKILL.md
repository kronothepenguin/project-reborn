# Working tasks

A slave works one task and reports to its master. The master and the user decide.

A task is a task file, or a brief in the slave's prompt for work without behaviours. The brief stands in for the task
file: its goal for `# Goal` and `# Steps`, its scope for `scope`, its skills for `skills`, its checks for `# Checks`, and
its slug for `<feature>-<NN>`. With a brief, step 1 reads the brief and loads its skills, and steps 4 and 7.1 are
skipped.

## 1. Read

Read the task file, the feature's `spec.md` and `plan.md`, and each file under `# Context`. Load each skill in
`skills`. The task's `# Goal` names the behaviours of `spec.md` it implements.

## 2. Worktree

The worktree and the branch are both named `<feature>-<NN>`, from the task's feature folder and number:

```sh
git worktree add -b <feature>-<NN> .claude/worktrees/<feature>-<NN> main
```

Work there.

## 3. Steps

Do the steps of `# Steps`. Change only the folders in `scope`.

## 4. Tests

Write one test per behaviour that `# Goal` names, with the `testing-behaviours` skill.

## 5. Checks

Run the commands under `# Checks`, the checks of every project changed, and the checks of every project that depends
on those. Each project's knowledge says how to run them. A failing check starts a review of the code, with the
`testing-behaviours` skill.

## 6. Knowledge

Update the knowledge files the change makes stale, in the project's own `knowledge/` folder.

## 7. Finish

Run in this order. Run each command on its own and read its result before the next.

1. Delete the task file.
2. Commit with a one-line title that starts with `feat:`, `fix:`, `refactor:` or `docs:`. Stage explicit paths.
3. In the worktree: `git merge main`. Re-run the checks when the merge brought changes. On a conflict in a generated
   `index.md` (it starts with `<!-- generated by index.py -->`), take either side, run `index.py` of the
   `documenting-with-okf` skill with no argument and commit the result.
4. From the main checkout: `git merge --ff-only <feature>-<NN>`. When it is refused, repeat from step 3.
5. When step 4 succeeds, from the main checkout: `git worktree remove .claude/worktrees/<feature>-<NN>`, then
   `git branch -d <feature>-<NN>`. Add `--force` to the remove only when `git status` in the worktree is clean and
   ignored files such as `node_modules` block it.

## 8. Report

Report to the master, in this shape:

```markdown
Changed: <what changed, by path>
Tests:
- <test name>: <behaviour of spec.md it proves>
Checks:
- <command>: <pass or fail, with the failure>
Where the code contradicted a source:
- <source>: <what the code does instead>
Facts for other tasks:
- <fact>: <the task or feature it serves>
Open questions:
- <question>
```

## Open questions

A question that the task or the brief, the spec and the plan leave open stops the work: report it, and the master
asks the user.
