# Decisions

Design decisions confirmed by the user, numbered in the order they were taken. Accepted text is never rewritten; a
change supersedes a decision with a new one. The branch rule every plan follows is
`plans/holo-port/decisions/0097-no-agent-works-on-main.md`.

## Process

- [0001 The game server's plan lives in plans/server](/decisions/0001-plan-in-plans-server.md) — plans/server is an OKF bundle in the format of plans/holo-port, worked through a tracking-plans skill shared by every plan, and Claude Code loads the project skills through a .claude/skills link.
- [0003 tools/create makes fullstack, backend and client projects](/decisions/0003-create-templates.md) — tools/create takes -template=fullstack|backend|client; fullstack is today's output and the default, backend is a Go package and runner only, and client is a Vite package like client-r26.
- [0004 The deleted server is the model for the structure](/decisions/0004-old-server-is-the-model.md) — The packages/server removed in commit 2ea51d7b is the model for the new server's structure, with separate receive and send interfaces for TCP and WebSocket, the encoding, and a protocol package with one part per client cast.
- [0017 The client template derives its Vite port from the name, in a range of its own](/decisions/0017-client-vite-port.md) — tools/create gives a client project the Vite dev server port 30000 + fnv32a("vite:" + name) % 10000, derived from the name as the Astro port is, in the range 30000 to 39999 that no other port uses.
- [0018 A client project builds as a plain Vite app](/decisions/0018-client-is-a-plain-vite-app.md) — A project made with tools/create -template=client builds as a page of its own, pnpm build writing dist/index.html and dist/assets/index-<hash>.js, and its vite.config.js holds only the derived port.
- [0024 Go package names drop the dash](/decisions/0024-go-package-names-drop-the-dash.md) — The backend and fullstack templates of tools/create name the Go package after the project without its dashes, so game-server holds package gameserver, while folders and module paths keep the dash.
- [0025 tools/create refuses names whose Go package cannot compile](/decisions/0025-refuse-names-whose-go-package-cannot-compile.md) — validateName refuses, with a plain message, a name whose Go package name cannot compile in the template being made, main, a Go keyword or a name the template's own Go already uses, and every generated project stays as it is.
- [0026 tools/create refuses the names the go tool treats specially as folders](/decisions/0026-refuse-names-the-go-tool-treats-specially.md) — For the backend and fullstack templates, validateName refuses internal, vendor and testdata, whose folders the go tool treats specially, with a plain message; the client template, which has no Go, keeps accepting them.

## Program and packages

- [0002 The game server is packages/server and apps/server, with no web pages](/decisions/0002-server-app.md) — The program is called server; packages/server holds it and apps/server runs it, as a TCP listener and a WebSocket server without web pages, created with the backend template of tools/create.
- [0005 The server lives in packages/server, and virtual holds only state](/decisions/0005-package-layout.md) — packages/server is one Go module with the transport, the encoding, the r26 protocol and the protocol-free game rules, and packages/virtual holds only the server's state.
- [0006 TCP and WebSocket are one byte-stream Conn, and the WebSocket mounts on any HTTP mux](/decisions/0006-transport.md) — The protocol code sees every connection as an io.Reader to receive and an io.Writer to send, TCP and golang.org/x/net/websocket both provide them, and the WebSocket is an http.Handler mounted with Mount(mux).
- [0022 StartInfo and StartMus start the listeners](/decisions/0022-start-info-and-start-mus.md) — packages/server defines StartInfo and StartMus, which open the listeners of server.info and server.mus, return an error when they cannot listen and then serve in the background; the standalone runner calls both, and the orchestrator will call the same two.

## Protocol

- [0007 r26 is the protocol package, and each listener names its protocol](/decisions/0007-protocols-per-listener.md) — The R26 protocol is a Go package named r26, each TCP address or WebSocket path names the protocol it speaks, r18 stays a door left open, and whether r18 and r26 players share one hotel is documented both ways. **Superseded by [0019](/decisions/0019-info-and-mus-listeners.md).**
- [0019 The server listens as server.info and server.mus, each on a TCP port, a WebSocket path or both](/decisions/0019-info-and-mus-listeners.md) — config.json gives the client's two connections, info and mus, a TCP port and a WebSocket path each, either or both; info speaks r26, and the rest of 0007 stands. **Superseded by [0020](/decisions/0020-info-and-mus-websocket-ports.md).**
- [0020 info and mus each listen as a WebSocket on a host and port of their own](/decisions/0020-info-and-mus-websocket-ports.md) — config.json gives info and mus a host and a port each, and the server runs a WebSocket listener on each, which is what LibreShockwave opens; TCP and WebSocket paths wait for later.
- [0008 The R26 protocol comes from the client's .ls scripts](/decisions/0008-reverse-engineer-ls-only.md) — The protocol is reverse engineered from the Lingo .ls scripts of packages/client-r26/src/game, never from the .js translations, covering every Handler Class and every other script that registers or sends messages.
- [0012 The server skips the client's encryption](/decisions/0012-no-encryption.md) — At login the server answers the client's public key with ENDOFCRYPTOPARAMS, as the old server did, so the client sends plain bytes, with no Diffie-Hellman key exchange and no RC4. **Superseded by [0027 The server sends ENDOFCRYPTOPARAMS right after CRYPTOPARAMETERS](/decisions/0027-endofcryptoparams-right-after-cryptoparameters.md).**

- [0014 Text on the wire is UTF-8](/decisions/0014-text-is-utf8.md) — The server reads and writes every string as UTF-8, and the external variables the site serves turn client.textdata.utf8 on so that the client does the same.
- [0015 The client runs on LibreShockwave, and every socket is a WebSocket](/decisions/0015-client-on-libreshockwave.md) — The R26 .dcr runs in the browser on LibreShockwave, which turns each of the client's sockets, #info and #mus, into a WebSocket carrying the same bytes as TCP; the #mus connection speaks the Multiuser Xtra's SMUS protocol, learned from LibreShockwave's source.
- [0016 The Holograph Emulator is a reference, never a port](/decisions/0016-holoemu-is-a-reference.md) — The Holograph Emulator's source in source/holoemu is read only when the client's .ls scripts are not enough for reverse engineering; the server neither translates it nor follows its structure.
- [0021 An unhandled packet is logged by its id, its name and its size](/decisions/0021-unhandled-packets-logged-by-id-name-and-size.md) — A packet the server does not handle yet is logged as one line with the session's address, the command's id, its name when r26 knows it, and the body's size; the body itself is never logged.
- [0023 Until S7, the mus listener accepts, logs sizes and never answers](/decisions/0023-mus-listener-before-s7.md) — Until S7 frames MUS, the mus listener accepts the WebSocket and logs the connect, the size of each message and the close, and it never answers.

## State and data

- [0009 packages/virtual holds the server's hot data and temporary data](/decisions/0009-virtual-holds-the-server-state.md) — The server's state lives in packages/virtual as hot data, saved data copied from the database while it is in use, and temporary data that lives only in memory and is gone after a restart.
- [0010 A change to hot data reaches the database at once](/decisions/0010-hot-data-written-at-once.md) — When saved data changes in the game, the handler writes the row and then updates memory, so a crash or a restart loses nothing, and temporary data never touches the database.
- [0011 What the server saves and what lives only in memory](/decisions/0011-saved-and-memory-only-data.md) — Placed furni, last time online, friend requests, room rights, bans, rating, chat history, furni state, ignore lists and the Game Hall of Fame are saved; positions, loaded rooms, who is online, instant messages and room events live only in memory.
- [0013 Changes from the site reach the server like Holo's MUS commands](/decisions/0013-site-changes-like-mus.md) — When the CMS or housekeeping changes something the server holds, the server is told, as Holo told its emulator with MUS commands, and under the orchestrator the CMS and housekeeping change the virtual state directly.

## Login and session

- [0027 The server sends ENDOFCRYPTOPARAMS right after CRYPTOPARAMETERS](/decisions/0027-endofcryptoparams-right-after-cryptoparameters.md) — The server still skips the client's encryption, but answers INIT_CRYPTO with CRYPTOPARAMETERS 0 and ENDOFCRYPTOPARAMS at once, without waiting for GENERATEKEY, which the client sometimes never sends.
- [0028 Habbos log in with SSO tickets only](/decisions/0028-sso-only.md) — The client's own login box is refused: TRY_LOGIN gets 33 login incorrect, and a habbo logs in only with SSO and a ticket from the CMS, so passwords never travel over the game connection.
- [0029 A second login closes the first session](/decisions/0029-a-second-login-closes-the-first.md) — When a habbo who is online logs in again, the old session gets 287 with reason 2, which sends its client to the page url_logout_concurrent, and is closed; the new session logs in.
- [0030 SSO tickets come from the CMS sign-in and live as long as its session](/decisions/0030-sso-tickets-from-the-cms-sign-in.md) — Signing in to the CMS creates an SSO ticket for the active habbo, apart from the session's private token, kept as text so the CMS renders it into the client page and the game server compares it; it is spent once used and dies with the session.
- [0031 A habbo's fuses: a default set, club fuses, and staff fuses from access groups](/decisions/0031-fuses-defaults-club-and-access-groups.md) — Every habbo gets fuse_trade and fuse_buy_credits, club members also fuse_use_club_dance and fuse_use_special_room_layouts, and the other 14 fuses the client checks come from access groups, through a fuse catalogue beside the site's attributes.
- [0032 The hotel is always open](/decisions/0032-the-hotel-is-always-open.md) — The server never sends the opening-hours messages 290 to 294, and never refuses a login for the time of day.
- [0033 The server accepts one client version, from the site](/decisions/0033-one-client-version-from-the-site.md) — A setting holds the client version the server accepts; VERSIONCHECK must carry it, and its client and external variables URLs must start with site.url, or the client is turned away; the client's links come from site.url too.
- [0034 The session parameters are settings](/decisions/0034-session-parameters-are-settings.md) — The ten session parameters are settings of the settings catalogue, edited in housekeeping like the CMS's other settings, with defaults that keep what no script reads at 0.
- [0035 The machine id is saved with the habbo at each login](/decisions/0035-the-machine-id-is-saved-per-habbo.md) — The machine id the client sends with UNIQUEID before it logs in is kept with the session and saved with the habbo once the login names it, at each login, ready for machine bans.
- [0036 Latency reports are only logged](/decisions/0036-latency-reports-are-logged.md) — The client's REPORT_LATENCY is written to the server's log, and nothing of it is saved.
- [0037 The last time online is written at login and at logout](/decisions/0037-last-online-at-login-and-logout.md) — A habbo's last time online, saved by decision 0011, is written when the habbo logs in and when they log out.
- [0038 A habbo's sound setting is saved](/decisions/0038-the-sound-setting-is-saved.md) — The sound setting the client reads at login and changes with the room bar is saved with the habbo.
- [0039 Rules tell sessions about events through an interface each session implements](/decisions/0039-rules-notify-sessions-through-an-interface.md) — game defines an interface that each session implements, such as Notify(event), with events as Go structs; a rule finds the habbos concerned in virtual and calls each one's session, and r26's session turns the event into its message.
- [0040 The accepted client version starts at 1](/decisions/0040-the-accepted-client-version-starts-at-1.md) — The setting that holds the client version the server accepts starts at 1, and the external variables the site serves give the client client.version.id=1.
- [0041 An empty VERSIONCHECK URL passes the check](/decisions/0041-an-empty-versioncheck-url-passes.md) — The version check accepts an empty client or external variables URL, which the client sends while its game host is local; a URL that is not empty must start with site.url.
- [0042 The server pings every 30 seconds and closes a session after 90 seconds without PONG](/decisions/0042-ping-every-30-seconds.md) — Two settings: the server sends PING every 30 seconds, and closes a session that has sent no PONG for 90 seconds, which logs its habbo out.
- [0044 What the game server saves of a habbo has a table of its own](/decisions/0044-game-login-data-has-its-own-table.md) — The last time online, the machine id of the last game login and the sound setting live in avatar_game_data, one row per habbo, not in columns of avatars, which many queries read whole.
