# Decisions

Design decisions confirmed by the user, numbered in the order they were taken. Accepted text is never rewritten; a
change supersedes a decision with a new one. The branch rule every plan follows is
`knowledge/decisions/holo-port/0097-no-agent-works-on-main.md`.

## Process

- [0001 The game server's plan lives in plans/server](/decisions/server/0001-plan-in-plans-server.md) — plans/server is an OKF bundle in the format of plans/holo-port, worked through a tracking-plans skill shared by every plan, and Claude Code loads the project skills through a .claude/skills link. **Superseded by [the workflow](/workflow.md).**
- [0003 tools/create makes fullstack, backend and client projects](/decisions/server/0003-create-templates.md) — tools/create takes -template=fullstack|backend|client; fullstack is today's output and the default, backend is a Go package and runner only, and client is a Vite package like client-r26.
- [0004 The deleted server is the model for the structure](/decisions/server/0004-old-server-is-the-model.md) — The packages/server removed in commit 2ea51d7b is the model for the new server's structure, with separate receive and send interfaces for TCP and WebSocket, the encoding, and a protocol package with one part per client cast.
- [0017 The client template derives its Vite port from the name, in a range of its own](/decisions/server/0017-client-vite-port.md) — tools/create gives a client project the Vite dev server port 30000 + fnv32a("vite:" + name) % 10000, derived from the name as the Astro port is, in the range 30000 to 39999 that no other port uses.
- [0018 A client project builds as a plain Vite app](/decisions/server/0018-client-is-a-plain-vite-app.md) — A project made with tools/create -template=client builds as a page of its own, pnpm build writing dist/index.html and dist/assets/index-<hash>.js, and its vite.config.js holds only the derived port.
- [0024 Go package names drop the dash](/decisions/server/0024-go-package-names-drop-the-dash.md) — The backend and fullstack templates of tools/create name the Go package after the project without its dashes, so game-server holds package gameserver, while folders and module paths keep the dash.
- [0025 tools/create refuses names whose Go package cannot compile](/decisions/server/0025-refuse-names-whose-go-package-cannot-compile.md) — validateName refuses, with a plain message, a name whose Go package name cannot compile in the template being made, main, a Go keyword or a name the template's own Go already uses, and every generated project stays as it is.
- [0026 tools/create refuses the names the go tool treats specially as folders](/decisions/server/0026-refuse-names-the-go-tool-treats-specially.md) — For the backend and fullstack templates, validateName refuses internal, vendor and testdata, whose folders the go tool treats specially, with a plain message; the client template, which has no Go, keeps accepting them.

## Program and packages

- [0002 The game server is packages/server and apps/server, with no web pages](/decisions/server/0002-server-app.md) — The program is called server; packages/server holds it and apps/server runs it, as a TCP listener and a WebSocket server without web pages, created with the backend template of tools/create.
- [0005 The server lives in packages/server, and virtual holds only state](/decisions/server/0005-package-layout.md) — packages/server is one Go module with the transport, the encoding, the r26 protocol and the protocol-free game rules, and packages/virtual holds only the server's state.
- [0006 TCP and WebSocket are one byte-stream Conn, and the WebSocket mounts on any HTTP mux](/decisions/server/0006-transport.md) — The protocol code sees every connection as an io.Reader to receive and an io.Writer to send, TCP and golang.org/x/net/websocket both provide them, and the WebSocket is an http.Handler mounted with Mount(mux).
- [0022 StartInfo and StartMus start the listeners](/decisions/server/0022-start-info-and-start-mus.md) — packages/server defines StartInfo and StartMus, which open the listeners of server.info and server.mus, return an error when they cannot listen and then serve in the background; the standalone runner calls both, and the orchestrator will call the same two.

## Protocol

- [0007 r26 is the protocol package, and each listener names its protocol](/decisions/server/0007-protocols-per-listener.md) — The R26 protocol is a Go package named r26, each TCP address or WebSocket path names the protocol it speaks, r18 stays a door left open, and whether r18 and r26 players share one hotel is documented both ways. **Superseded by [0019](/decisions/server/0019-info-and-mus-listeners.md).**
- [0019 The server listens as server.info and server.mus, each on a TCP port, a WebSocket path or both](/decisions/server/0019-info-and-mus-listeners.md) — config.json gives the client's two connections, info and mus, a TCP port and a WebSocket path each, either or both; info speaks r26, and the rest of 0007 stands. **Superseded by [0020](/decisions/server/0020-info-and-mus-websocket-ports.md).**
- [0020 info and mus each listen as a WebSocket on a host and port of their own](/decisions/server/0020-info-and-mus-websocket-ports.md) — config.json gives info and mus a host and a port each, and the server runs a WebSocket listener on each, which is what LibreShockwave opens; TCP and WebSocket paths wait for later.
- [0008 The R26 protocol comes from the client's .ls scripts](/decisions/server/0008-reverse-engineer-ls-only.md) — The protocol is reverse engineered from the Lingo .ls scripts of packages/client-r26/src/game, never from the .js translations, covering every Handler Class and every other script that registers or sends messages.
- [0012 The server skips the client's encryption](/decisions/server/0012-no-encryption.md) — At login the server answers the client's public key with ENDOFCRYPTOPARAMS, as the old server did, so the client sends plain bytes, with no Diffie-Hellman key exchange and no RC4. **Superseded by [0027 The server sends ENDOFCRYPTOPARAMS right after CRYPTOPARAMETERS](/decisions/server/0027-endofcryptoparams-right-after-cryptoparameters.md).**

- [0014 Text on the wire is UTF-8](/decisions/server/0014-text-is-utf8.md) — The server reads and writes every string as UTF-8, and the external variables the site serves turn client.textdata.utf8 on so that the client does the same.
- [0015 The client runs on LibreShockwave, and every socket is a WebSocket](/decisions/server/0015-client-on-libreshockwave.md) — The R26 .dcr runs in the browser on LibreShockwave, which turns each of the client's sockets, #info and #mus, into a WebSocket carrying the same bytes as TCP; the #mus connection speaks the Multiuser Xtra's SMUS protocol, learned from LibreShockwave's source.
- [0016 The Holograph Emulator is a reference, never a port](/decisions/server/0016-holoemu-is-a-reference.md) — The Holograph Emulator's source in source/holoemu is read only when the client's .ls scripts are not enough for reverse engineering; the server neither translates it nor follows its structure.
- [0021 An unhandled packet is logged by its id, its name and its size](/decisions/server/0021-unhandled-packets-logged-by-id-name-and-size.md) — A packet the server does not handle yet is logged as one line with the session's address, the command's id, its name when r26 knows it, and the body's size; the body itself is never logged.
- [0023 Until S7, the mus listener accepts, logs sizes and never answers](/decisions/server/0023-mus-listener-before-s7.md) — Until S7 frames MUS, the mus listener accepts the WebSocket and logs the connect, the size of each message and the close, and it never answers.

## State and data

- [0009 packages/virtual holds the server's hot data and temporary data](/decisions/server/0009-virtual-holds-the-server-state.md) — The server's state lives in packages/virtual as hot data, saved data copied from the database while it is in use, and temporary data that lives only in memory and is gone after a restart.
- [0010 A change to hot data reaches the database at once](/decisions/server/0010-hot-data-written-at-once.md) — When saved data changes in the game, the handler writes the row and then updates memory, so a crash or a restart loses nothing, and temporary data never touches the database.
- [0011 What the server saves and what lives only in memory](/decisions/server/0011-saved-and-memory-only-data.md) — Placed furni, last time online, friend requests, room rights, bans, rating, chat history, furni state, ignore lists and the Game Hall of Fame are saved; positions, loaded rooms, who is online, instant messages and room events live only in memory.
- [0013 Changes from the site reach the server like Holo's MUS commands](/decisions/server/0013-site-changes-like-mus.md) — When the CMS or housekeeping changes something the server holds, the server is told, as Holo told its emulator with MUS commands, and under the orchestrator the CMS and housekeeping change the virtual state directly.

## Login and session

- [0027 The server sends ENDOFCRYPTOPARAMS right after CRYPTOPARAMETERS](/decisions/server/0027-endofcryptoparams-right-after-cryptoparameters.md) — The server still skips the client's encryption, but answers INIT_CRYPTO with CRYPTOPARAMETERS 0 and ENDOFCRYPTOPARAMS at once, without waiting for GENERATEKEY, which the client sometimes never sends.
- [0028 Habbos log in with SSO tickets only](/decisions/server/0028-sso-only.md) — The client's own login box is refused: TRY_LOGIN gets 33 login incorrect, and a habbo logs in only with SSO and a ticket from the CMS, so passwords never travel over the game connection.
- [0029 A second login closes the first session](/decisions/server/0029-a-second-login-closes-the-first.md) — When a habbo who is online logs in again, the old session gets 287 with reason 2, which sends its client to the page url_logout_concurrent, and is closed; the new session logs in.
- [0030 SSO tickets come from the CMS sign-in and live as long as its session](/decisions/server/0030-sso-tickets-from-the-cms-sign-in.md) — Signing in to the CMS creates an SSO ticket for the active habbo, apart from the session's private token, kept as text so the CMS renders it into the client page and the game server compares it; it is spent once used and dies with the session.
- [0031 A habbo's fuses: a default set, club fuses, and staff fuses from access groups](/decisions/server/0031-fuses-defaults-club-and-access-groups.md) — Every habbo gets fuse_trade and fuse_buy_credits, club members also fuse_use_club_dance and fuse_use_special_room_layouts, and the other 14 fuses the client checks come from access groups, through a fuse catalogue beside the site's attributes. **Superseded by [0045 A habbo's fuses: everyone's two, Holo's club set, and every checked fuse from access groups](/decisions/server/0045-fuses-holos-club-set-and-every-checked-fuse.md).**
- [0032 The hotel is always open](/decisions/server/0032-the-hotel-is-always-open.md) — The server never sends the opening-hours messages 290 to 294, and never refuses a login for the time of day.
- [0033 The server accepts one client version, from the site](/decisions/server/0033-one-client-version-from-the-site.md) — A setting holds the client version the server accepts; VERSIONCHECK must carry it, and its client and external variables URLs must start with site.url, or the client is turned away; the client's links come from site.url too.
- [0034 The session parameters are settings](/decisions/server/0034-session-parameters-are-settings.md) — The ten session parameters are settings of the settings catalogue, edited in housekeeping like the CMS's other settings, with defaults that keep what no script reads at 0.
- [0035 The machine id is saved with the habbo at each login](/decisions/server/0035-the-machine-id-is-saved-per-habbo.md) — The machine id the client sends with UNIQUEID before it logs in is kept with the session and saved with the habbo once the login names it, at each login, ready for machine bans.
- [0036 Latency reports are only logged](/decisions/server/0036-latency-reports-are-logged.md) — The client's REPORT_LATENCY is written to the server's log, and nothing of it is saved.
- [0037 The last time online is written at login and at logout](/decisions/server/0037-last-online-at-login-and-logout.md) — A habbo's last time online, saved by decision 0011, is written when the habbo logs in and when they log out.
- [0038 A habbo's sound setting is saved](/decisions/server/0038-the-sound-setting-is-saved.md) — The sound setting the client reads at login and changes with the room bar is saved with the habbo.
- [0039 Rules tell sessions about events through an interface each session implements](/decisions/server/0039-rules-notify-sessions-through-an-interface.md) — game defines an interface that each session implements, such as Notify(event), with events as Go structs; a rule finds the habbos concerned in virtual and calls each one's session, and r26's session turns the event into its message.
- [0040 The accepted client version starts at 1](/decisions/server/0040-the-accepted-client-version-starts-at-1.md) — The setting that holds the client version the server accepts starts at 1, and the external variables the site serves give the client client.version.id=1.
- [0041 An empty VERSIONCHECK URL passes the check](/decisions/server/0041-an-empty-versioncheck-url-passes.md) — The version check accepts an empty client or external variables URL, which the client sends while its game host is local; a URL that is not empty must start with site.url.
- [0042 The server pings every 30 seconds and closes a session after 90 seconds without PONG](/decisions/server/0042-ping-every-30-seconds.md) — Two settings: the server sends PING every 30 seconds, and closes a session that has sent no PONG for 90 seconds, which logs its habbo out.
- [0043 The sign-in's SSO ticket is best-effort, and update 0008 waits for an administrator](/decisions/server/0043-the-sign-in-ticket-is-best-effort.md) — Signing in to the CMS makes its SSO ticket after the session and only logs a failure, which happens only while the update that gives sso_tickets its new form waits; that update is not automatic, and the client page makes a ticket whenever none is valid.
- [0044 What the game server saves of a habbo has a table of its own](/decisions/server/0044-game-login-data-has-its-own-table.md) — The last time online, the machine id of the last game login and the sound setting live in avatar_game_data, one row per habbo, not in columns of avatars, which many queries read whole.
- [0045 A habbo's fuses: everyone's two, Holo's club set, and every checked fuse from access groups](/decisions/server/0045-fuses-holos-club-set-and-every-checked-fuse.md) — Every habbo gets fuse_trade and fuse_buy_credits, a club member also the club dance, the special room layouts and the habbo and furni choosers, as Holo's rank 2 did, and access groups grant the 31 fuses the client or Holo's server checks, through a fuse catalogue beside the site's attributes.
- [0046 The first fuses follow Holo's ranks by level](/decisions/server/0046-the-first-fuses-follow-holos-ranks.md) — An update gives every access group the fuses Holo's ranks held up to the group's level, with the ranks of Holo's newest dump, and level 7 for the fuses that dump does not rank.
- [0047 The online habbos live in virtual/habbo](/decisions/server/0047-online-habbos-in-virtual-habbo.md) — The habbos online in the game are package-level state in packages/virtual/habbo, package habbo, loaded at login and dropped at logout.
- [0048 An online habbo keeps its session through an interface virtual declares](/decisions/server/0048-sessions-through-an-interface-virtual-declares.md) — virtual/habbo declares the Session interface, Notify(event any), and keeps each online habbo with its session; game.Session is that same interface and the events are game's structs.
- [0049 A client with the wrong version is closed after its error](/decisions/server/0049-a-wrong-version-is-closed.md) — A VERSIONCHECK that fails gets 33 Version not correct, and the server then closes the connection; an SSO before a VERSIONCHECK that passed is turned away the same way.
- [0050 The game server loads the settings and reloads them like the CMS](/decisions/server/0050-the-server-loads-and-reloads-the-settings.md) — server.New loads the settings, panicking when it cannot, and reloads them every cms.refresh seconds while no update waits, as cms.New does.
- [0051 A habbo has no achievements yet](/decisions/server/0051-no-achievements-yet.md) — 436 lists no achievements and the server sends no 437, so GETSELECTEDBADGES, which the client sends only after a 437, waits for the phase that brings achievements.
- [0052 The club status splits the club's days by club.daysPerMonth](/decisions/server/0052-club-status-by-days-per-month.md) — Message 7 gives the days of the running period, 1 to club.daysPerMonth, the whole periods prepaid after it, and the whole periods of club the user has had, with response 1, which opens no window.
- [0053 The online habbo holds its badges, its sound setting and its fuses](/decisions/server/0053-the-online-habbo-holds-its-own-data.md) — game.Login loads the habbo's badges, sound setting and fuses into virtual/habbo; the wallet and the club, which the user's habbos share, are read from the store when the client asks.
- [0054 Error reports wait for S7](/decisions/server/0054-error-reports-wait-for-s7.md) — The client sends no error report, and the server sends no 299 in S2: a command the server cannot answer is logged and closes the session, and S7 decides when the server reports an error.
- [0055 A hotel starts with Holo's categories, public rooms and room models](/decisions/server/0055-holos-navigator-set.md) — An update seeds Holo's English categories, its 12 public rooms with their casts and its 42 room models; BattleBall and SnowStorm wait for S8.
- [0056 A habbo's own rooms follow Holo's rules](/decisions/server/0056-own-rooms-follow-holos-rules.md) — Up to 50 rooms per habbo, names of 1 to 50 characters without a filter, the client's three doors, passwords of 1 to 32 characters, and 10 to 25 visitors, 25 by default.
- [0057 The recommended rooms are three random habbo rooms](/decisions/server/0057-three-random-recommended-rooms.md) — GET_RECOMMENDED_ROOMS gets three habbo rooms drawn at random each time the client asks, as Holo did.
- [0058 Favourite rooms are saved, up to 30](/decisions/server/0058-favourites-saved-up-to-30.md) — A habbo's favourite rooms are saved per habbo, up to 30, a setting; one more gets 33 Only 10 favorite rooms allowed!, which the client shows as its own text.
- [0059 A deleted room's furni goes to its owner's hand](/decisions/server/0059-a-deleted-rooms-furni-goes-to-its-owner.md) — When a habbo deletes a room, the furni in it goes to the hand of the habbo that owns the room, so nothing bought is lost.
- [0060 The navigator's shared data lives in virtual/category, virtual/model and virtual/room](/decisions/server/0060-virtual-category-model-and-room.md) — virtual/category holds the categories, virtual/model the room models, and virtual/room the public rooms and, from S4, the loaded rooms and who is in them.
- [0061 A navigator list shows at most 30 rooms](/decisions/server/0061-navigator-lists-show-up-to-30-rooms.md) — A category's habbo rooms and a search's results are each capped at 30 rooms, two settings, as Holo capped them.
- [0062 Room passwords are stored hashed](/decisions/server/0062-room-passwords-are-hashed.md) — A room's password is stored as a hash, like the users' passwords, and entering a room compares the typed password with it; nobody can read it back.
- [0063 Public rooms and habbo rooms have tables of their own](/decisions/server/0063-public-rooms-and-habbo-rooms-apart.md) — public_rooms and rooms each keep only their own columns, so a habbo room's owner is NOT NULL, and a favourite names one or the other.
- [0064 The game server starts while updates wait, and loads the navigator once they are applied](/decisions/server/0064-the-navigator-loads-once-the-updates-are-applied.md) — server.New loads the navigator's shared data when no database update waits; otherwise it logs that the navigator waits, and loads it as soon as the updates are applied, checked with the settings' reload.
- [0065 Habbos walk a step every 500 ms, by Holo's rules](/decisions/server/0065-walking-500-ms-by-holos-rules.md) — The server moves a walking habbo one tile every 500 ms, the client's own step time, in 8 directions, a diagonal only when both tiles beside it are free, and up or down at most 1 height.
- [0066 Staff read the chat history in housekeeping, and it is kept 30 days](/decisions/server/0066-staff-read-the-chat-history-30-days.md) — A housekeeping page behind a new attribute searches the saved chat by room or habbo, as HoloCMS's did, and lines older than 30 days, a setting, are deleted.
- [0067 A room ban lasts 15 minutes](/decisions/server/0067-a-room-ban-lasts-15-minutes.md) — An owner's ban keeps the habbo out of that room for 15 minutes, a setting, as Holo's did.
- [0068 A habbo shows its favourite group's badge in rooms](/decisions/server/0068-a-habbo-shows-its-favourite-groups-badge.md) — In a room a habbo shows the badge of its favourite group from the site, or none, and 309 lists the badges of the groups shown.
- [0069 The doorbell, the room queue and the spectators live only in memory](/decisions/server/0069-doorbell-queue-and-spectators-in-memory.md) — Habbos waiting at a doorbell, in a full room's queue, or watching as spectators are kept only in memory, as positions are.
- [0070 Rooms show a loading ad and a room ad from housekeeping's settings](/decisions/server/0070-a-loading-ad-and-a-room-ad-from-settings.md) — 258 shows a loading ad and 208 a room ad, each an image URL and a link held by settings that housekeeping edits; empty settings show none.
- [0071 An empty room unloads at once](/decisions/server/0071-an-empty-room-unloads-at-once.md) — The last habbo to leave a room unloads it from memory, and the next one in loads it again from the store, as Holo did.
- [0072 Each loaded room runs its own clock](/decisions/server/0072-each-loaded-room-runs-its-own-clock.md) — A loaded room runs a clock of its own from its load to its unload; every 500 ms it moves all its walking habbos one tile and sends one status message with all of them, as Holo's thread per room did.
- [0073 Each session sends through an outbox](/decisions/server/0073-each-session-sends-through-an-outbox.md) — A session queues its outgoing messages, which a goroutine of its own writes, so sending never waits; a client whose queue is full has stopped reading and is closed; the queue holds game.outboxSize messages, 500.
- [0074 Near habbos read chat, far ones see a bubble](/decisions/server/0074-near-habbos-read-chat-far-ones-see-a-bubble.md) — Habbos within game.chatRange tiles each way, 5, read a habbo's chat, as Holo had it; farther ones get the line without its text, which the client draws as its unheard bubble. Shouts reach everyone.
- [0075 Talking, smileys and waves animate as Holo did](/decisions/server/0075-talking-smileys-and-waves-as-holo.md) — After each line a speaker shows talk for (letters + 50) x 30 ms; a smiley in chat or a shout shows its face for 5 s; a wave lasts 1.5 s and stops a dance. The room's clock ends each.
- [0076 A habbo ignores up to 100 habbos, the oldest dropped](/decisions/server/0076-ignore-up-to-100-the-oldest-dropped.md) — A habbo's ignore list holds game.maxIgnoredHabbos habbos, 100; ignoring one more drops the oldest, which the client shows with the answer 2.
- [0077 The word filter waits for a task of its own](/decisions/server/0077-the-word-filter-waits.md) — Chat is not filtered in S4; the moderation feature's later notes keep Holo's word filter for one task that covers chat, room names and messages.
- [0078 A chat line is cut at 100 characters](/decisions/server/0078-a-chat-line-is-cut-at-100-characters.md) — The server keeps the first game.chatMaxLength characters, 100, of a chat, shout or whisper, and shows and saves those.
- [0079 A kicked or banned habbo walks out](/decisions/server/0079-a-kicked-habbo-walks-out.md) — A habbo kicked or banned from a habbo room can walk nowhere else, walks to the door a step every 500 ms, and leaves the room there; one that cannot reach the door leaves at once.
- [0080 Full rooms queue habbos and take spectators in S4](/decisions/server/0080-full-rooms-queue-and-take-spectators-in-s4.md) — S4 builds the R26 client's queue for a full room and its spectator mode, in a task of their own whose details are asked when it starts.
- [0081 Rooms have 11 event types, as Holo](/decisions/server/0081-eleven-room-event-types.md) — Room events have the types 1 to game.roomEventTypes, 11, which the client names from its texts; only a room's owner hosts an event there, one at a time, until it leaves the room or logs out.
- [0082 A room's rating is the sum of its votes and the share of +1](/decisions/server/0082-a-rating-is-the-sum-and-the-share-of-up-votes.md) — 345 carries -1 until the habbo votes, then the sum of the room's votes, never below 0, with the share of +1 votes as the percent; it goes to everyone in the room who has voted.
- [0083 A habbo wears up to five badges, in slots](/decisions/server/0083-a-habbo-wears-five-badges-in-slots.md) — The store keeps a slot, 1 to 5, for each badge a habbo wears, as the R26 client's badge window sets them; the site's badge page changes to match.
- [0084 The game server prunes the chat history hourly](/decisions/server/0084-the-game-server-prunes-the-chat-hourly.md) — The game server, which saves the chat, deletes the lines older than game.chatHistoryDays when it starts and every hour after.
- [0085 The Chat Log Viewer lists 100 lines a page](/decisions/server/0085-the-chat-log-viewer-pages-by-100.md) — The Chat Log Viewer lists what a search finds newest first, 100 lines a page, with the Newer and Older links of the Staff Logs.
- [0086 The Chat Log Viewer marks public rooms](/decisions/server/0086-the-chat-log-marks-public-rooms.md) — The Room ID column shows a habbo room's id and Public before a public room's; a search for an id finds both kinds, and a deleted room's lines show -.
- [0087 Every full room queues its arrivals](/decisions/server/0087-every-full-room-queues.md) — A full public room or habbo room puts an arriving habbo in its queue, 259, in place of refusing it, and lets the next one in when a place frees.
- [0088 Club members come first in a queue](/decisions/server/0088-club-members-first-in-a-queue.md) — A room's queue holds two lines, club members, then everyone else, and a place goes to the club line first.
- [0089 Up to 50 spectators watch a full room, from its queue](/decisions/server/0089-up-to-50-spectators-from-the-queue.md) — A habbo waiting for a full room can switch to the spectators' line; up to game.maxSpectators, 50, watch at once, and a spectator leaving lets the next one in.
- [0090 The queue sets are room and spectators](/decisions/server/0090-queue-sets-room-and-spectators.md) — 259 names the room's line room, target 1, and the spectators' spectators, target 2, which the client's texts queue_set.<name>.info take as keys.
- [0091 A hotel starts with Holo's catalogue, changed by database updates](/decisions/server/0091-holos-catalogue-changed-by-updates.md) — An update seeds Holo's English catalogue, 76 pages, 1,372 furni and 19 deals; no page edits it in S5, a change is another update, and a housekeeping editor waits in the furnis feature's later notes.
- [0092 A trade lives only in memory](/decisions/server/0092-a-trade-lives-only-in-memory.md) — An open trade is temporary data; furni stays in its owner's hand until both habbos accept, then changes hands in the database in one transaction, and a restart, a disconnect or leaving the room closes the trade.
- [0093 A recycling is saved](/decisions/server/0093-a-recycling-is-saved.md) — The furni a habbo gives the recycler leave its hand and wait in the database with the time the recycling started, so a restart changes nothing; the habbo takes the reward, which destroys them, or cancels and gets them back.
- [0094 Any habbo sends a present to any habbo](/decisions/server/0094-any-habbo-sends-a-present-to-any-habbo.md) — Any catalogue furni can be bought as a present for any habbo by name, online or not; it waits in a box in the receiver's hand with its note, an unknown name charges nothing, and the buyer's credit history names the furni and the receiver.
